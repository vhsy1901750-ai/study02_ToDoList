# 할 일 관리 앱 PRD

## 1. 개요

매일 10-20개 정도의 할 일을 관리하는 개인용 웹 앱이다. 브라우저에서 바로 실행되고, 새로고침해도 데이터가 유지된다. 빌드 도구나 프레임워크 없이 순수 자바스크립트(ES 모듈)로 만든다.

### 목표

- 할 일을 빠르게 추가, 수정, 삭제하고 완료 여부를 체크할 수 있다.
- 업무, 개인, 공부 카테고리로 나눠 볼 수 있다.
- 지금 보고 있는 범위의 진행률을 한눈에 확인할 수 있다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 남아 있다.
- PC와 휴대폰 브라우저 모두에서 쓸 수 있다.

### 제외 범위

다음 기능은 만들지 않는다.

- 날짜별 목록, 매일 자동 초기화
- 우선순위, 마감일, 메모
- 정렬 변경, 드래그 앤 드롭, 검색
- 기기 간 동기화, 계정, 서버 저장

## 2. 사용자와 사용 방식

- 사용자: 본인 한 명
- 사용 규모: 동시에 10-20개 안팎의 할 일
- 목록 방식: 날짜 구분 없는 **단일 목록**이다. 끝난 일은 직접 삭제하거나 "완료 항목 정리"로 비운다.

## 3. 기능 요구사항

### 3.1 화면 구성

한 페이지로 구성하며, 위에서 아래로 다음 순서로 배치한다.

1. 제목: "할 일"
2. 오류 안내 영역 (오류가 있을 때만 표시, 6장 참고)
3. 진행률
4. 카테고리 탭
5. 추가 폼
6. 할 일 목록
7. 완료 항목 정리 버튼

### 3.2 진행률

- 막대와 함께 `완료 3 / 전체 8 (38%)` 형식으로 표시한다.
- **현재 선택된 카테고리 탭 기준**으로 계산한다. `전체` 탭이면 모든 할 일이 기준이다.
- 퍼센트는 `Math.round(done / total * 100)`으로 반올림한다. 예: 1/3 → 33%
- 할 일이 0개이면 `완료 0 / 전체 0 (0%)`으로 표시한다.

### 3.3 카테고리 탭

- 탭: 전체, 업무, 개인, 공부
- 탭을 고르면 목록과 진행률이 해당 카테고리 기준으로 바뀐다.
- 마지막으로 선택한 탭은 저장되어 새로고침 후에도 유지된다.

### 3.4 할 일 추가

- 입력 요소: 제목 입력칸, 카테고리 선택, 추가 버튼
- 추가 버튼이나 Enter로 추가한다.
- 제목은 앞뒤 공백을 제거한 뒤 저장한다. 비어 있으면 추가하지 않는다.
- 제목은 최대 100자다(입력칸 `maxlength="100"`).
- 카테고리 선택의 기본값: 특정 카테고리 탭을 보고 있으면 그 카테고리, `전체` 탭이면 `업무`
- 추가 후 제목 입력칸을 비우고 포커스를 유지한다.
- 새 항목은 목록 맨 아래에 붙는다.

### 3.5 할 일 목록

- 각 항목: 완료 체크박스, 제목, 카테고리 라벨, 수정 버튼, 삭제 버튼
- 순서: 추가한 순서(`createdAt` 오름차순)를 유지한다. 완료해도 위치가 바뀌지 않는다.
- 완료된 항목은 제목에 취소선을 긋는다.
- 현재 탭에 보일 항목이 없으면 "할 일이 없습니다."를 표시한다.

### 3.6 완료 체크

- 체크박스를 누르면 완료와 미완료가 바뀐다.
- 진행률이 즉시 갱신된다.

### 3.7 할 일 수정

- 수정 버튼을 누르면 해당 항목이 그 자리에서 제목 입력칸, 카테고리 선택, 저장 버튼, 취소 버튼으로 바뀐다.
- Enter나 저장 버튼으로 저장하고, Esc나 취소 버튼으로 취소한다.
- 제목 규칙은 추가와 같다. 공백 제거 후 비어 있으면 저장하지 않고 수정 상태를 유지한다.
- 한 번에 한 항목만 수정 상태가 될 수 있다. 다른 항목의 수정 버튼을 누르면 이전 수정은 저장하지 않고 닫힌다.
- 수정 중에 다른 동작(추가, 완료 체크, 삭제, 탭 변경, 완료 항목 정리)을 하면 수정 상태는 저장하지 않고 닫힌다.
- 카테고리를 바꿔서 현재 탭에 맞지 않게 되면, 저장 후 목록에서 사라진다.

### 3.8 할 일 삭제

- 삭제 버튼을 누르면 확인 창(`confirm`)을 띄운다. 확인하면 삭제한다.

### 3.9 완료 항목 정리

- 현재 탭에 보이는 완료 항목을 확인 창을 거쳐 한꺼번에 삭제한다. `전체` 탭이면 모든 완료 항목이 대상이다.
- 현재 탭에 완료 항목이 없으면 버튼을 비활성화한다.

## 4. 비기능 요구사항

- **실행 환경**: 최신 Chrome, Edge, Safari, Firefox. HTTPS 또는 localhost에서 서빙되어야 한다. `index.html`을 파일로 직접 여는 방식(`file://`)은 지원하지 않는다. ES 모듈과 `crypto.randomUUID()`가 이 환경을 요구하기 때문이다.
- **반응형**: 360px 폭에서 가로 스크롤 없이 쓸 수 있다. 버튼과 체크박스는 손가락으로 누르기 충분한 크기(최소 44px 높이)로 만든다.
- **보안**: 사용자가 입력한 제목은 `textContent`로만 화면에 넣는다. `innerHTML`에 사용자 입력을 넣지 않는다.
- **의존성**: 런타임과 테스트 모두 외부 패키지를 쓰지 않는다.
- **성능**: 상태가 바뀔 때마다 화면 전체를 다시 그린다. 항목이 수십 개 수준이므로 별도 최적화는 하지 않는다.

## 5. 데이터 모델과 저장

### 5.1 할 일

```js
{
  id: "3f2a…",              // crypto.randomUUID()
  title: "보고서 초안",       // 공백 제거됨, 1-100자
  category: "work",         // "work" | "personal" | "study"
  done: false,
  createdAt: 1790000000000  // 추가 시각(ms)
}
```

화면 표시 이름은 코드 한 곳에서만 매핑한다.

```js
const CATEGORIES = { work: "업무", personal: "개인", study: "공부" };
```

### 5.2 앱 상태

```js
{
  version: 1,
  todos: [ /* 할 일 배열 */ ],
  filter: "all"             // "all" | "work" | "personal" | "study"
}
```

- 수정 중인 항목 id(`editingId`)는 화면 상태일 뿐이므로 저장하지 않는다.

### 5.3 저장

- localStorage 키 `todo-app`에 앱 상태 전체를 JSON 문자열로 저장한다.
- 추가, 수정, 완료 체크, 삭제, 완료 항목 정리, 탭 변경 때마다 전체 상태를 저장한다.
- `version`은 나중에 데이터 구조를 바꿀 때 옛 데이터를 구분하기 위한 표시다. 지금은 변환 로직을 만들지 않는다.

### 5.4 데이터 유지 범위

- 데이터는 브라우저와 기기마다 따로 저장된다. PC와 휴대폰의 목록은 동기화되지 않는다.
- 브라우저의 사이트 데이터를 지우면 할 일도 함께 사라진다.

## 6. 오류 처리

| 상황 | 동작 | 화면 안내 |
|---|---|---|
| 저장된 값이 없음 (처음 실행) | 빈 목록, `전체` 탭으로 시작 | 없음 |
| 저장된 값이 깨짐 (JSON 파싱 실패, 형식 불일치) | 원본 문자열을 `todo-app-backup` 키에 옮기고 빈 목록으로 시작 | "저장된 데이터를 읽지 못해 빈 목록으로 시작합니다." |
| 저장 실패 (브라우저가 저장소를 막은 경우 등) | 화면의 상태는 유지 | "변경 사항을 저장하지 못했습니다. 브라우저 저장소 설정을 확인해 주세요." |
| 빈 제목으로 추가 또는 수정 | 무시 (수정은 수정 상태 유지) | 없음 |

"형식 불일치"는 다음 중 하나라도 해당하는 경우다.

- 최상위 값이 객체가 아니거나 `version`이 `1`이 아님
- `todos`가 배열이 아님
- 할 일 중 하나라도 5.1의 필드 규칙을 어김
- `filter`가 허용된 값이 아님

## 7. 구조

### 7.1 파일 구성

```
index.html          화면 뼈대
style.css           스타일 (반응형 포함)
src/
  todo-store.js     상태 변경, 계산, 직렬화 (순수 함수)
  todo-view.js      상태를 받아 DOM을 그림
  app.js            진입점: 상태 보관, 이벤트 연결, localStorage 읽기/쓰기
tests/
  todo-store.test.js
package.json        "type": "module"과 test 스크립트만 (의존성 없음)
```

### 7.2 모듈 역할

**todo-store.js**: DOM과 localStorage를 모른다. 모든 변경 함수는 상태를 받아 **새 상태를 반환**하며 원본을 바꾸지 않는다. 잘못된 입력(빈 제목, 없는 id, 허용되지 않은 카테고리나 필터)이면 받은 상태를 그대로 반환한다.

| 종류 | 함수 |
|---|---|
| 생성 | `createInitialState()` |
| 변경 | `addTodo(state, { title, category })`, `updateTodo(state, id, { title, category })`, `toggleTodo(state, id)`, `deleteTodo(state, id)`, `clearCompleted(state)`, `setFilter(state, filter)` |
| 계산 | `getVisibleTodos(state)`, `getProgress(state)` → `{ done, total, percent }` |
| 직렬화 | `serializeState(state)` → 문자열, `parseState(raw)` → `{ state, error }` |

- `parseState(null)`은 초기 상태와 `error: null`을 반환한다.
- `parseState`가 깨진 값을 받으면 초기 상태와 `error: "corrupt"`를 반환한다.

**todo-view.js**: `render(state, editingId)` 하나로 진행률, 탭, 목록, 완료 항목 정리 버튼 상태를 모두 다시 그린다. 오류 안내 표시 함수도 여기에 둔다.

**app.js**: `state`와 `editingId` 변수를 가지고, localStorage 접근과 오류 처리를 담당한다. 목록 이벤트는 `<ul>` 하나에 위임하고 각 버튼의 `data-action`, `data-id`로 동작을 구분한다.

### 7.3 데이터 흐름

```
사용자 동작 → app.js 이벤트 핸들러
           → todo-store 함수로 새 상태 계산
           → localStorage에 저장 (실패 시 안내 표시)
           → todo-view.render()로 화면 갱신
```

앱 시작 시에는 localStorage 읽기 → `parseState` → (깨졌으면 백업과 안내) → 첫 `render` 순서로 진행한다.

## 8. 테스트

### 8.1 자동 테스트

`npm test`(`node --test`)로 `todo-store.js`를 검증한다.

- 추가: 공백 제거, 빈 제목 거부, 허용되지 않은 카테고리 거부, 맨 뒤에 추가됨
- 수정: 제목과 카테고리 변경, 빈 제목 거부, 없는 id면 상태 그대로
- 완료 토글, 삭제: 없는 id면 상태 그대로
- 완료 항목 정리: 현재 탭의 완료 항목만 지움
- 탭 변경: 허용되지 않은 값 거부
- `getVisibleTodos`: 탭별로 맞게 거름
- `getProgress`: 0개일 때 0%, 반올림(1/3 → 33%), 현재 탭 기준
- 불변성: 변경 함수 호출 후 원본 상태가 그대로임
- `parseState`: 값 없음, 깨진 JSON, 형식 불일치 각 경우, 정상 데이터 왕복(`serializeState` → `parseState`)

### 8.2 수동 확인 체크리스트

- [ ] 추가(버튼, Enter), 빈 제목 무시
- [ ] 수정(Enter 저장, Esc 취소, 빈 제목 거부)
- [ ] 완료 체크 시 취소선과 진행률 갱신
- [ ] 삭제 확인 창, 완료 항목 정리 확인 창과 비활성화 상태
- [ ] 탭 전환 시 목록과 진행률 변경
- [ ] 새로고침 후 목록과 선택한 탭 유지
- [ ] 제목에 `<b>굵게</b>`를 넣으면 글자 그대로 보임
- [ ] 개발자 도구에서 `todo-app` 값을 깨뜨린 뒤 새로고침하면 안내가 뜨고 `todo-app-backup`에 원본이 남음
- [ ] 360px 폭에서 가로 스크롤 없음

## 9. 배포

- GitHub Pages(HTTPS 정적 호스팅)에 올린다. 빌드 단계는 없다.
- 개발 중에는 로컬 정적 서버(예: VS Code Live Server)로 연다.

## 10. 완료 기준

다음을 모두 만족해야 완료로 본다.

1. 자동 테스트가 모두 통과한다.
2. 로컬에서 8.2 수동 체크리스트를 모두 통과한다.
3. **배포된 URL에서** PC와 휴대폰으로 8.2 체크리스트를 다시 통과한다. 로컬에서 통과한 것만으로는 완료로 보지 않는다.
