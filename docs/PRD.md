# 할 일 관리 앱 PRD

이 문서는 할 일 관리 앱을 무엇을, 어떻게 만들지 정리한 안내서입니다. 기능을 고치거나 새로 더할 때 먼저 이 문서를 확인해 주세요.

## 1. 개요

매일 10-20개 정도의 할 일을 관리하는 개인용 웹 앱입니다. 브라우저에서 바로 실행되고, 새로고침해도 데이터가 그대로 남아 있습니다. 빌드 도구나 프레임워크 없이 순수 자바스크립트(ES 모듈)로 만듭니다.

### 목표

이 앱으로 할 수 있어야 하는 일은 다음과 같습니다.

- 할 일을 빠르게 추가, 수정, 삭제하고 완료 여부를 체크할 수 있습니다.
- 업무, 개인, 공부 카테고리로 나눠 볼 수 있습니다.
- 지금 보고 있는 범위의 진행률을 한눈에 확인할 수 있습니다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 남아 있습니다.
- PC와 휴대폰 브라우저 모두에서 쓸 수 있습니다.

### 만들지 않는 기능

아래 기능은 이번 범위에 넣지 않습니다.

- 날짜별 목록, 매일 자동 초기화
- 우선순위, 마감일, 메모
- 정렬 변경, 드래그 앤 드롭, 검색
- 기기 간 동기화, 계정, 서버 저장

## 2. 누가, 어떻게 쓰나요

사용자는 본인 한 명이고, 동시에 10-20개 안팎의 할 일을 다룹니다.

목록은 날짜 구분 없는 **단일 목록**입니다. 끝난 일은 직접 삭제하거나 "완료 항목 정리"로 한꺼번에 비웁니다.

## 3. 기능 안내

### 3.1 화면 구성

화면은 한 페이지이며, 위에서부터 다음 순서로 놓입니다.

1. 제목 "할 일"
2. 오류 안내 영역 (오류가 있을 때만 나타납니다. 6장을 참고해 주세요.)
3. 진행률
4. 카테고리 탭
5. 추가 폼
6. 할 일 목록
7. 완료 항목 정리 버튼

### 3.2 진행률

진행률은 막대와 함께 `완료 3 / 전체 8 (38%)` 형식으로 보여 줍니다.

계산 기준은 **현재 선택된 카테고리 탭**입니다. `전체` 탭이면 모든 할 일이 기준이 됩니다. 퍼센트는 `Math.round(done / total * 100)`으로 반올림하므로, 예를 들어 3개 중 1개를 끝내면 33%가 됩니다. 할 일이 하나도 없을 때는 `완료 0 / 전체 0 (0%)`으로 표시합니다.

### 3.3 카테고리 탭

탭은 전체, 업무, 개인, 공부 네 가지입니다. 탭을 고르면 목록과 진행률이 그 카테고리 기준으로 바뀝니다. 마지막으로 고른 탭은 저장되므로, 새로고침한 뒤에도 그대로 유지됩니다.

### 3.4 할 일 추가

추가 폼은 제목 입력칸, 카테고리 선택, 추가 버튼으로 이뤄집니다. 추가 버튼을 누르거나 Enter를 누르면 할 일이 추가됩니다.

제목은 다음 규칙을 따릅니다.

- 앞뒤 공백을 지운 뒤 저장합니다. 지우고 나서 비어 있으면 추가하지 않습니다.
- 최대 100자까지 쓸 수 있습니다(입력칸 `maxlength="100"`).

카테고리 선택의 기본값은 지금 보고 있는 탭에 따라 정해집니다. 특정 카테고리 탭을 보고 있으면 그 카테고리가, `전체` 탭이면 `업무`가 미리 선택됩니다.

추가가 끝나면 제목 입력칸을 비우고, 커서는 입력칸에 그대로 둡니다. 새 항목은 목록 맨 아래에 붙습니다.

### 3.5 할 일 목록

각 항목에는 완료 체크박스, 제목, 카테고리 라벨, 수정 버튼, 삭제 버튼이 있습니다.

목록은 추가한 순서(`createdAt` 오름차순)를 지킵니다. 완료해도 위치가 바뀌지 않으며, 완료된 항목은 제목에 취소선을 긋습니다. 현재 탭에 보일 항목이 없으면 "할 일이 없습니다."를 표시합니다.

### 3.6 완료 체크

체크박스를 누르면 완료와 미완료가 서로 바뀌고, 진행률도 곧바로 갱신됩니다.

### 3.7 할 일 수정

수정 버튼을 누르면 그 항목이 제자리에서 제목 입력칸, 카테고리 선택, 저장 버튼, 취소 버튼으로 바뀝니다. Enter나 저장 버튼으로 저장하고, Esc나 취소 버튼으로 취소합니다.

수정할 때는 다음 사항을 지켜 주세요.

- 제목 규칙은 추가할 때와 같습니다. 공백을 지운 뒤 비어 있으면 저장하지 않고, 수정 상태를 그대로 유지합니다.
- 한 번에 한 항목만 수정할 수 있습니다. 다른 항목의 수정 버튼을 누르면 이전 수정은 저장하지 않고 닫힙니다.
- 수정 중에 다른 동작(추가, 완료 체크, 삭제, 탭 변경, 완료 항목 정리)을 하면 수정 상태는 저장하지 않고 닫힙니다.
- 카테고리를 바꿔서 현재 탭과 맞지 않게 되면, 저장한 뒤 목록에서 사라집니다.

### 3.8 할 일 삭제

삭제 버튼을 누르면 확인 창(`confirm`)이 뜨고, 확인하면 삭제합니다.

### 3.9 완료 항목 정리

현재 탭에 보이는 완료 항목을 확인 창을 거쳐 한꺼번에 삭제합니다. `전체` 탭이면 모든 완료 항목이 대상입니다. 현재 탭에 완료 항목이 없으면 버튼을 비활성화합니다.

## 4. 지켜야 할 조건

| 항목 | 내용 |
| --- | --- |
| 실행 환경 | 최신 Chrome, Edge, Safari, Firefox에서 동작해야 하며, HTTPS 또는 localhost에서 서빙되어야 합니다. `index.html`을 파일로 직접 여는 방식(`file://`)은 지원하지 않습니다. ES 모듈과 `crypto.randomUUID()`가 이 환경을 요구하기 때문입니다. |
| 반응형 | 360px 폭에서 가로 스크롤 없이 쓸 수 있어야 합니다. 버튼과 체크박스는 손가락으로 누르기 충분한 크기(최소 44px 높이)로 만듭니다. |
| 보안 | 사용자가 입력한 제목은 `textContent`로만 화면에 넣습니다. `innerHTML`에 사용자 입력을 넣지 않습니다. |
| 의존성 | 런타임과 테스트 모두 외부 패키지를 쓰지 않습니다. |
| 성능 | 상태가 바뀔 때마다 화면 전체를 다시 그립니다. 항목이 수십 개 수준이므로 따로 최적화하지 않습니다. |

## 5. 데이터는 이렇게 저장합니다

### 5.1 할 일 한 건

할 일 하나는 다음 다섯 가지 정보를 가집니다.

| 필드 | 뜻 | 예시 |
| --- | --- | --- |
| `id` | `crypto.randomUUID()`로 만든 고유 번호 | `"3f2a…"` |
| `title` | 제목. 공백을 지운 1-100자 | `"보고서 초안"` |
| `category` | `"work"`, `"personal"`, `"study"` 중 하나 | `"work"` |
| `done` | 완료 여부 | `false` |
| `createdAt` | 추가한 시각(ms) | `1790000000000` |

화면에 보이는 카테고리 이름은 코드 한 곳(`CATEGORIES`)에서만 정합니다. `work`는 업무, `personal`은 개인, `study`는 공부로 표시합니다.

### 5.2 앱 상태

앱 전체 상태는 다음 세 가지로 이뤄집니다.

| 필드 | 뜻 |
| --- | --- |
| `version` | 저장 형식 버전. 지금은 `1`입니다. |
| `todos` | 할 일 목록(배열) |
| `filter` | 선택된 탭. `"all"`, `"work"`, `"personal"`, `"study"` 중 하나입니다. |

수정 중인 항목의 id(`editingId`)는 화면에서만 쓰는 정보이므로 저장하지 않습니다.

### 5.3 저장 방법

앱 상태 전체를 JSON 문자열로 바꿔 localStorage의 `todoApp.v1` 키에 저장합니다. 예전 이름인 `todo-app` 키에 저장된 데이터가 있으면, 처음 열 때 한 번 `todoApp.v1`로 옮기고 예전 키는 지웁니다. 추가, 수정, 완료 체크, 삭제, 완료 항목 정리, 탭 변경이 일어날 때마다 상태 전체를 저장합니다.

`version`은 나중에 데이터 구조를 바꿀 때 옛 데이터를 알아보기 위한 표시입니다. 지금은 옛 데이터를 변환하는 로직을 만들지 않습니다.

### 5.4 데이터가 남는 범위

데이터는 브라우저와 기기마다 따로 저장되므로, PC와 휴대폰의 목록은 서로 이어지지 않습니다. 브라우저의 사이트 데이터를 지우면 할 일도 함께 사라집니다.

## 6. 문제가 생겼을 때

| 상황 | 앱의 동작 | 화면 안내 |
| --- | --- | --- |
| 저장된 값이 없음 (처음 실행) | 빈 목록, `전체` 탭으로 시작합니다. | 없음 |
| 저장된 값이 깨짐 (JSON 파싱 실패, 형식 불일치) | 원본 문자열을 `todoApp.v1.backup` 키에 옮기고 빈 목록으로 시작합니다. | "저장된 데이터를 읽지 못해 빈 목록으로 시작합니다." |
| 저장 실패 (브라우저가 저장소를 막은 경우 등) | 화면의 상태는 그대로 유지합니다. | "변경 사항을 저장하지 못했습니다. 브라우저 저장소 설정을 확인해 주세요." |
| 빈 제목으로 추가 또는 수정 | 무시합니다. 수정 중이었다면 수정 상태를 유지합니다. | 없음 |

여기서 "형식 불일치"는 다음 중 하나라도 해당하는 경우를 말합니다.

- 최상위 값이 객체가 아니거나 `version`이 `1`이 아닌 경우
- `todos`가 배열이 아닌 경우
- 할 일 중 하나라도 5.1의 필드 규칙을 어기는 경우
- `filter`가 허용된 값이 아닌 경우

## 7. 구조

### 7.1 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 데스크톱 버전 화면 뼈대 (기본 주소) |
| `mobile_version/index.html` | 모바일 버전 화면 뼈대 |
| `style.css` | 두 버전이 함께 쓰는 스타일 (색, 다크 모드, 버튼, 목록) |
| `desktop.css` | 데스크톱 버전 전용 배치 (2단, 1단) |
| `src/ui-prefs.js` | 다크 모드와 레이아웃 설정을 적용하고 기억합니다. |
| `src/todo-store.js` | 상태 변경, 계산, 직렬화 (순수 함수) |
| `src/todo-view.js` | 상태를 받아 DOM을 그립니다. |
| `src/app.js` | 진입점. 상태 보관, 이벤트 연결, localStorage 읽기와 쓰기를 맡습니다. |
| `tests/todo-store.test.js` | `todo-store.js` 테스트 |
| `package.json` | `"type": "module"`과 test 스크립트만 있습니다(의존성 없음). |

### 7.2 모듈별 역할

**todo-store.js**는 DOM과 localStorage를 모릅니다. 모든 변경 함수는 상태를 받아 **새 상태를 돌려주며** 원본은 바꾸지 않습니다. 잘못된 입력(빈 제목, 없는 id, 허용되지 않은 카테고리나 필터)을 받으면 받은 상태를 그대로 돌려줍니다. 이 파일이 제공하는 함수는 다음과 같습니다.

| 종류 | 함수 |
| --- | --- |
| 생성 | `createInitialState()` |
| 변경 | `addTodo(state, { title, category })`, `updateTodo(state, id, { title, category })`, `toggleTodo(state, id)`, `deleteTodo(state, id)`, `clearCompleted(state)`, `setFilter(state, filter)` |
| 계산 | `getVisibleTodos(state)`, `getProgress(state)` → `{ done, total, percent }` |
| 직렬화 | `serializeState(state)` → 문자열, `parseState(raw)` → `{ state, error }` |

`parseState(null)`은 초기 상태와 `error: null`을 돌려줍니다. 깨진 값을 받으면 초기 상태와 `error: "corrupt"`를 돌려줍니다.

**todo-view.js**는 `render(state, editingId)` 하나로 진행률, 탭, 목록, 완료 항목 정리 버튼 상태를 모두 다시 그립니다. 오류 안내를 표시하는 함수도 이 파일에 둡니다.

**app.js**는 `state`와 `editingId` 변수를 가지고 localStorage 접근과 오류 처리를 맡습니다. 목록 이벤트는 `<ul>` 하나에 위임하고, 각 버튼의 `data-action`, `data-id`로 어떤 동작인지 구분합니다.

### 7.3 데이터가 흐르는 순서

사용자가 무언가를 하면 다음 순서로 처리됩니다.

1. `app.js`의 이벤트 핸들러가 동작을 받습니다.
2. `todo-store`의 함수로 새 상태를 계산합니다.
3. 새 상태를 localStorage에 저장합니다. 실패하면 안내를 표시합니다.
4. `todo-view`의 `render()`로 화면을 갱신합니다.

앱을 처음 열 때는 localStorage를 읽고, `parseState`로 확인한 뒤(깨졌다면 백업하고 안내합니다), 첫 `render`를 합니다.

## 8. 테스트

### 8.1 자동 테스트

`npm test`(`node --test`)로 `todo-store.js`를 검증합니다. 확인하는 내용은 다음과 같습니다.

| 대상 | 확인하는 내용 |
| --- | --- |
| 추가 | 공백 제거, 빈 제목 거부, 허용되지 않은 카테고리 거부, 맨 뒤에 추가됨 |
| 수정 | 제목과 카테고리 변경, 빈 제목 거부, 없는 id면 상태 그대로 |
| 완료 토글, 삭제 | 없는 id면 상태 그대로 |
| 완료 항목 정리 | 현재 탭의 완료 항목만 지움 |
| 탭 변경 | 허용되지 않은 값 거부 |
| `getVisibleTodos` | 탭별로 맞게 거름 |
| `getProgress` | 0개일 때 0%, 반올림(1/3 → 33%), 현재 탭 기준 |
| 불변성 | 변경 함수를 호출한 뒤에도 원본 상태가 그대로임 |
| `parseState` | 값 없음, 깨진 JSON, 형식 불일치 각 경우, 정상 데이터 왕복(`serializeState` → `parseState`) |

### 8.2 직접 확인할 항목

브라우저에서 아래 항목을 하나씩 확인해 주세요.

- [ ] 추가(버튼, Enter)가 되고, 빈 제목은 무시됩니다.
- [ ] 수정이 됩니다(Enter로 저장, Esc로 취소, 빈 제목 거부).
- [ ] 완료 체크 시 취소선이 생기고 진행률이 갱신됩니다.
- [ ] 삭제 확인 창, 완료 항목 정리 확인 창이 뜨고, 정리 버튼의 비활성화 상태가 맞습니다.
- [ ] 탭을 바꾸면 목록과 진행률이 바뀝니다.
- [ ] 새로고침한 뒤에도 목록과 선택한 탭이 유지됩니다.
- [ ] 제목에 `<b>굵게</b>`를 넣으면 글자 그대로 보입니다.
- [ ] 개발자 도구에서 `todoApp.v1` 값을 깨뜨린 뒤 새로고침하면 안내가 뜨고, `todoApp.v1.backup`에 원본이 남습니다.
- [ ] 360px 폭에서 가로 스크롤이 생기지 않습니다.
- [ ] 다크 모드 토글을 누르면 색이 바뀌고, 새로고침해도 유지됩니다. 두 버전 모두 확인합니다.
- [ ] 데스크톱 버전에서 레이아웃 토글을 누르면 2단과 1단이 바뀌고, 새로고침해도 유지됩니다.
- [ ] 한 버전에서 추가한 할 일이 다른 버전에서도 보입니다.

## 9. 배포

GitHub Pages(HTTPS 정적 호스팅)에 올립니다. 빌드 단계는 없습니다. 개발 중에는 로컬 정적 서버(예: VS Code Live Server)로 열어 확인합니다.

## 10. 완료 기준

다음 세 가지를 모두 만족해야 완료로 봅니다.

1. 자동 테스트가 모두 통과합니다.
2. 로컬에서 8.2의 확인 항목을 모두 통과합니다.
3. **배포된 URL에서** PC와 휴대폰으로 8.2의 확인 항목을 다시 통과합니다. 로컬에서 통과한 것만으로는 완료로 보지 않습니다.

## 11. 데스크톱 버전과 화면 설정

### 11.1 두 버전

| 버전 | 주소 | 배치 |
| --- | --- | --- |
| 데스크톱 버전 | 기본 주소 (`/`) | 넓은 화면을 쓰는 2단 배치. 1단으로도 바꿀 수 있습니다. |
| 모바일 버전 | `/mobile_version/` | 처음 만든 1단 배치를 그대로 옮긴 것입니다. |

두 버전은 할 일 로직, 화면 그리기, 동작 연결 코드(`src/`)와 공통 스타일(`style.css`)을 함께 씁니다. 버전마다 다른 것은 화면 뼈대(`index.html`)와 배치뿐이므로, 기능을 고치면 두 버전에 함께 반영됩니다.

같은 주소에서 돌아가므로 저장소(`todoApp.v1`)도 함께 씁니다. 한 버전에서 적은 할 일이 다른 버전에도 그대로 보입니다.

### 11.2 데스크톱 배치

- **2단(기본)**: 왼쪽에 진행률과 카테고리 탭을 세로로 두고, 오른쪽에 추가 폼, 목록, 완료 항목 정리 버튼을 둡니다. 화면 전체 너비는 최대 1200px이며, 왼쪽 칸은 스크롤해도 화면에 붙어 있습니다.
- **1단**: 모바일 버전과 같은 순서로 한 줄에 쌓고, 너비는 최대 640px입니다.
- 화면 폭이 768px보다 좁으면 설정과 상관없이 1단으로 보이고, 레이아웃 토글은 숨깁니다.

### 11.3 화면 설정 토글

| 토글 | 있는 곳 | 동작 |
| --- | --- | --- |
| 레이아웃 | 데스크톱 버전 | 누를 때마다 2단과 1단이 바뀝니다. 버튼에는 바뀔 배치("1단으로 보기", "2단으로 보기")를 표시합니다. |
| 다크 모드 | 두 버전 모두 | 누를 때마다 라이트와 다크가 바뀝니다. 버튼에는 바뀔 모드("다크 모드", "라이트 모드")를 표시합니다. 한 번도 고르지 않았으면 기기의 다크 모드 설정을 따릅니다. |

토글 선택은 할 일 데이터와 따로 localStorage의 `todoApp.ui` 키에 `{ theme, layout }`으로 저장하고, 새로고침해도 유지합니다. 이 값을 읽지 못하면 기본값(기기 설정을 따르는 테마, 2단)으로 보여 줍니다.

테마는 첫 화면이 그려지기 전에 적용합니다. 그래야 다크 모드를 고른 사람에게 밝은 화면이 잠깐 비치지 않습니다.

다크 모드에서도 글자와 배경의 명도 대비는 4.5:1 이상이어야 합니다.
