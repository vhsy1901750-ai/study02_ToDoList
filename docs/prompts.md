# 할 일 관리 앱 단계별 프롬프트

[PRD](PRD.md)를 바탕으로 Claude Code에서 앱을 처음부터 만들 때 쓰는 프롬프트입니다. 다섯 단계로 나뉘어 있으며, 각 단계의 프롬프트 상자를 그대로 복사해 Claude Code에 붙여 넣으면 됩니다.

## 쓰는 방법

- **한 번에 한 단계씩** 진행해 주세요. 각 프롬프트는 "끝나면 멈추고 보고해 줘"로 끝나므로, 결과를 확인한 뒤 다음 단계를 붙여 넣습니다.
- 모든 단계는 저장소 루트에 `docs/PRD.md`가 있다고 가정합니다. 프롬프트 안의 "PRD 3.4절" 같은 표기는 그 문서의 절 번호입니다.
- 단계마다 끝에 있는 **완료 확인** 항목을 직접 확인한 뒤 넘어가 주세요. 확인이 안 되면 다음 단계로 가지 말고, 그 단계에서 고치도록 다시 요청합니다.

| 단계 | 하는 일 | 만들어지는 것 |
| --- | --- | --- |
| 1 | 프로젝트 준비와 할 일 로직 | `package.json`, `src/todo-store.js`, 테스트 |
| 2 | 저장 형식과 데이터 검증 | `serializeState`, `parseState`, 테스트 |
| 3 | 화면 구성과 렌더링 | `index.html`, `style.css`, `src/todo-view.js`, `src/app.js` |
| 4 | 사용자 동작 연결 | 추가, 체크, 수정, 삭제, 탭, 정리 동작 |
| 5 | 전체 점검과 배포 | GitHub Pages 배포, 배포 주소 확인 |

---

## 1단계: 프로젝트 준비와 할 일 로직

화면 없이 할 일 데이터를 다루는 핵심 로직을 테스트와 함께 만듭니다.

```text
docs/PRD.md를 읽고 할 일 관리 앱의 1단계를 진행해 줘. 이번 단계는 화면 없이 할 일 데이터를 다루는 로직만 만든다.

할 일:
1. package.json을 만들어 줘. 내용은 "type": "module"과 "test": "node --test" 스크립트만 넣고, 의존성은 하나도 넣지 마.
2. src/todo-store.js를 만들어 줘. DOM과 localStorage를 전혀 모르는 순수 함수 모음이어야 해 (PRD 7.2절).
   - 상수: CATEGORIES = { work: "업무", personal: "개인", study: "공부" }, FILTERS = ["all", "work", "personal", "study"], MAX_TITLE_LENGTH = 100
   - 함수: createInitialState, addTodo, updateTodo, toggleTodo, deleteTodo, setFilter, getVisibleTodos, getProgress, clearCompleted
3. tests/todo-store.test.js에 PRD 8.1절의 항목 중 저장 형식(parseState)을 뺀 나머지를 테스트로 만들어 줘.

반드시 지킬 것:
- 테스트를 먼저 쓰고, 실패하는 것을 확인한 다음 구현해 줘.
- 모든 변경 함수는 원본을 바꾸지 않고 새 상태를 돌려줘야 해.
- 잘못된 입력(빈 제목, 101자 이상 제목, 없는 id, 허용되지 않은 카테고리나 필터)이면 새 객체를 만들지 말고 받은 상태 객체를 그대로 돌려줘. 나중에 화면 코드가 "nextState !== state"로 변경 여부를 판단한다.
- 카테고리 검사는 Object.hasOwn으로 해 줘. "toString" 같은 값이 통과하면 안 된다.
- 진행률은 현재 탭 기준이고 Math.round로 반올림한다. 할 일이 0개면 0%다 (PRD 3.2절).
- 완료 항목 정리는 현재 탭에 보이는 완료 항목만 지운다 (PRD 3.9절).

끝나면 npm test 결과를 보여 주고, 커밋한 뒤 멈춰서 보고해 줘. 2단계는 내가 요청할 때까지 시작하지 마.
```

**완료 확인**
- `npm test`가 모두 통과합니다.
- `package.json`에 `dependencies`, `devDependencies`가 없습니다.

## 2단계: 저장 형식과 데이터 검증

새로고침해도 데이터가 남도록 상태를 문자열로 바꾸고, 망가진 저장 데이터를 알아보는 로직을 만듭니다.

```text
docs/PRD.md를 읽고 2단계를 진행해 줘. 1단계에서 만든 src/todo-store.js에 저장 형식 처리를 더한다.

할 일:
1. serializeState(state)를 만들어 줘. 상태를 JSON 문자열로 바꾼다.
2. parseState(raw)를 만들어 줘. 돌려주는 값은 { state, error }다.
   - raw가 null이면(처음 실행) 초기 상태와 error: null
   - JSON 파싱에 실패하거나 PRD 6절의 "형식 불일치"에 해당하면 초기 상태와 error: "corrupt"
   - 정상이면 읽은 상태와 error: null
3. 테스트를 추가해 줘. 값 없음, 깨진 JSON, 정상 데이터 왕복(serializeState → parseState), 그리고 형식 불일치는 경우마다 따로 테스트한다.

형식 불일치로 봐야 하는 경우 (하나라도 해당하면 corrupt):
- 최상위가 객체가 아니거나(null, 배열 포함) version이 1이 아님
- todos가 배열이 아님
- filter가 FILTERS에 없는 값임
- 할 일 중 하나라도 규칙을 어김: id가 빈 문자열이거나 문자열이 아님, 제목이 비었거나 101자 이상이거나 앞뒤에 공백이 있음, 카테고리가 허용 값이 아님, done이 불리언이 아님, createdAt이 숫자가 아님, 할 일 자체가 객체가 아님

반드시 지킬 것:
- 제목 검사는 1단계에서 만든 제목 정리 함수를 다시 써서 한 곳에서만 규칙을 관리해 줘.
- 이 파일에는 여전히 localStorage를 들이지 마. 실제 저장은 3단계에서 app.js가 맡는다.
- 테스트를 먼저 쓰고 실패를 확인한 뒤 구현해 줘.

끝나면 npm test 결과를 보여 주고, 커밋한 뒤 멈춰서 보고해 줘.
```

**완료 확인**
- `npm test`가 모두 통과하고, 형식 불일치 경우가 하나씩 따로 테스트돼 있습니다.

## 3단계: 화면 구성과 렌더링

저장된 데이터를 불러와 화면에 그립니다. 이 단계에서는 버튼이 아직 반응하지 않습니다.

```text
docs/PRD.md를 읽고 3단계를 진행해 줘. 이번 단계는 화면을 그리고 저장된 데이터를 불러오는 것까지만 한다. 버튼 동작은 4단계에서 연결한다.

할 일:
1. index.html: PRD 3.1절의 순서대로 제목, 오류 안내 영역(평소에는 숨김), 진행률 막대와 문구, 카테고리 탭, 추가 폼(제목 입력칸 maxlength="100", 카테고리 선택, 추가 버튼), 할 일 목록 <ul>, 완료 항목 정리 버튼을 배치해 줘. 스크립트는 <script type="module" src="src/app.js">로 불러온다.
2. style.css: 360px 폭에서 가로 스크롤이 없어야 하고, 버튼, 입력칸, 선택칸은 최소 높이 44px로 만들어 줘.
3. src/todo-view.js: render(state, editingId) 하나로 진행률, 탭, 목록, 완료 항목 정리 버튼 상태를 매번 전부 다시 그린다. 오류 안내를 띄우는 showNotice(message)와 카테고리 선택칸을 채우는 함수도 여기에 둔다.
4. src/app.js: localStorage의 "todoApp.v1" 값을 읽어 parseState로 확인하고 첫 화면을 그린다.

반드시 지킬 것:
- 사용자가 쓴 제목은 textContent나 value로만 화면에 넣어. innerHTML은 쓰지 마.
- 카테고리 이름(업무, 개인, 공부)은 todo-store.js의 CATEGORIES에서만 가져와. 다른 곳에 다시 적지 마.
- 탭 버튼에는 data-filter, 체크박스와 수정, 삭제 버튼에는 data-action과 data-id를 붙여 줘. 4단계에서 이벤트 위임에 쓴다.
- 체크박스는 44x44 크기의 <label>로 감싸 줘. 체크박스에 바깥 여백(margin)을 줘서 넓히는 방식은 안 된다. 여백은 눌리는 영역에 들어가지 않아서 실제로는 체크박스 크기만큼만 눌린다.
- 저장 데이터가 깨졌으면 원본 문자열을 "todoApp.v1.backup" 키에 옮긴 뒤 빈 목록으로 시작하고, "저장된 데이터를 읽지 못해 빈 목록으로 시작합니다."를 띄워 줘.
- localStorage 읽기나 쓰기가 예외를 던지면 "변경 사항을 저장하지 못했습니다. 브라우저 저장소 설정을 확인해 주세요."를 띄우고 앱은 계속 동작해야 해.
- 목록이 비면 "할 일이 없습니다."를 보여 줘.

확인 방법:
- index.html을 더블클릭해서 열면 ES 모듈이 막히니, 저장소 루트에서 python -m http.server 8000을 실행하고 http://localhost:8000/으로 열어 줘.
- 개발자 도구에서 샘플 데이터를 localStorage에 넣고 새로고침해서 진행률, 취소선, 탭 선택이 맞게 보이는지 확인해 줘.
- 제목이 "<b>굵게</b>"인 할 일이 글자 그대로 보이는지 확인해 줘.
- "todoApp.v1" 값을 "{"로 바꾸고 새로고침해서 안내 문구와 백업을 확인해 줘.
- 확인이 끝나면 localStorage를 비우고 서버를 꺼 줘.

끝나면 확인 결과를 항목별로 보고하고, 커밋한 뒤 멈춰 줘.
```

**완료 확인**
- 서버로 열었을 때 빈 상태 화면이 PRD 3.1절 순서대로 보입니다.
- 휴대폰 폭(360px)에서 가로 스크롤이 생기지 않습니다.

## 4단계: 사용자 동작 연결

추가, 완료 체크, 수정, 삭제, 탭 전환, 완료 항목 정리가 실제로 동작하게 연결합니다.

```text
docs/PRD.md를 읽고 4단계를 진행해 줘. 3단계에서 만든 화면에 사용자 동작을 연결한다. 대상은 PRD 3.4절부터 3.9절까지다.

할 일:
1. src/app.js에 update(nextState) 함수를 만들어 줘. 순서는 이렇다.
   ① 수정 중이던 항목을 닫는다(editingId = null).
   ② nextState가 지금 상태와 다른 객체일 때만 상태를 바꾸고 localStorage "todoApp.v1"에 저장한다.
   ③ 화면을 다시 그린다.
2. 추가: 폼 제출(버튼, Enter)로 추가한다. 성공했을 때만 입력칸을 비우고, 커서는 입력칸에 남긴다. 빈 제목은 무시한다.
3. 탭: 탭을 누르면 필터를 바꾸고 저장한다. 추가 폼의 카테고리 기본값을 그 탭으로 맞춘다(전체 탭이면 업무).
4. 완료 체크, 삭제: 목록 <ul> 하나에 click 이벤트를 위임하고 data-action으로 구분한다. 삭제는 "이 할 일을 삭제할까요?" 확인 창을 거친다.
5. 완료 항목 정리: "완료한 할 일 N개를 삭제할까요?" 확인 창을 거쳐 현재 탭의 완료 항목을 지운다.
6. 수정 (PRD 3.7절): 수정 버튼을 누르면 그 자리가 제목 입력칸, 카테고리 선택, 저장 버튼, 취소 버튼으로 바뀌고 입력칸에 커서가 간다.
   - Enter나 저장으로 저장하고, Esc나 취소로 취소한다.
   - 빈 제목이면 저장하지 않고 수정 화면을 그대로 둔다.
   - 한 번에 한 항목만 수정할 수 있다. 수정 중에 다른 동작(추가, 체크, 삭제, 탭 변경, 정리)을 하면 저장 없이 닫힌다. 다만 삭제나 정리 확인 창에서 취소하면 바뀐 것이 없으므로 수정 화면을 그대로 둔다.

반드시 지킬 것:
- 변경 여부는 todo-store 함수가 같은 객체를 돌려줬는지(nextState !== state)로만 판단해 줘.
- 이벤트 리스너는 다시 그려지지 않는 바깥 요소(#tabs, #todo-list, 폼)에만 붙여 줘.
- 저장 버튼에는 data-action을 붙이지 마. 폼 submit 이벤트로만 처리한다.

확인 방법:
- 3단계처럼 python -m http.server 8000으로 열고 PRD 8.2절 체크리스트를 처음부터 끝까지 실제로 눌러 보며 확인해 줘.
- 새로고침한 뒤 목록과 선택한 탭이 유지되는지 꼭 확인해 줘.

끝나면 체크리스트 항목별 결과를 보고하고, 커밋한 뒤 멈춰 줘.
```

**완료 확인**
- PRD 8.2절 체크리스트의 9개 항목이 모두 통과합니다.
- `npm test`가 여전히 통과합니다.

## 5단계: 전체 점검과 배포

GitHub Pages에 올리고, 배포된 주소에서 다시 확인합니다. 로컬에서 통과한 것만으로는 완료로 보지 않습니다 (PRD 10절).

```text
docs/PRD.md를 읽고 마지막 5단계를 진행해 줘. 앱을 GitHub Pages에 배포하고 배포된 주소에서 검증한다.

할 일:
1. 배포 전 점검: npm test를 실행하고, 로컬 서버에서 PRD 8.2절 체크리스트를 한 번 더 확인해 줘. 하나라도 실패하면 배포하지 말고 원인부터 찾아 줘.
2. 배포: main 브랜치를 GitHub에 push하고, 저장소 루트(/)를 서빙하도록 GitHub Pages를 켜 줘. 빌드 단계는 없다.
   push와 Pages 설정은 공개 저장소를 바꾸는 작업이니, 실행하기 직전에 나한테 한 번 확인받아 줘.
3. 배포 완료 확인: Pages 빌드 상태가 built가 될 때까지 기다려 줘.
4. 배포 주소 검증 (PC): 배포된 주소를 열고 아래를 확인해 줘.
   - style.css, src/app.js, src/todo-view.js, src/todo-store.js가 모두 200으로 받아지는지 (대소문자나 경로 오류 확인)
   - 콘솔에 오류가 없는지
   - PRD 8.2절 체크리스트 전체
   GitHub Pages는 파일을 약 10분 캐시하니, 확인 전에 강력 새로고침(Ctrl+F5)을 해 줘.
5. 휴대폰 확인 요청: 나한테 휴대폰으로 같은 주소를 열어 아래를 확인해 달라고 요청해 줘.
   - 가로 스크롤 없이 보이는지
   - 체크박스, 수정, 삭제 버튼이 손가락으로 무리 없이 눌리는지
   - 20-30자짜리 한글 제목이 읽기 괜찮은지
   - 한글 마지막 글자를 조합하는 중에 Enter를 눌러도 제목 전체가 저장되는지
   - 새로고침 후 데이터가 남아 있는지

반드시 지킬 것:
- 내가 휴대폰 확인 결과를 알려 주기 전에는 완료라고 보고하지 마.
- 확인하지 못한 항목이 있으면 숨기지 말고 그대로 보고해 줘.

끝나면 배포 주소와 항목별 검증 결과를 정리해서 보고해 줘.
```

**완료 확인**
- 배포 주소에서 PC와 휴대폰 모두 PRD 8.2절 체크리스트를 통과합니다.
- PRD 10절의 완료 기준 세 가지를 모두 만족합니다.
