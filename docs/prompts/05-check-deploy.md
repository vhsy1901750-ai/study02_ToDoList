# 5단계: 전체 점검과 배포

GitHub Pages에 올리고, 배포된 주소에서 다시 확인합니다. 로컬에서 통과한 것만으로는 완료로 보지 않습니다 (PRD 10절). 아래 상자의 내용을 그대로 복사해 Claude Code에 붙여 넣어 주세요.

```text
docs/PRD.md를 읽고 마지막 5단계를 진행해 줘. 앱을 GitHub Pages에 배포하고 배포된 주소에서 검증한다.

할 일:
1. 배포 전 점검: npm test를 실행하고, 로컬 서버에서 PRD 8.2절 체크리스트를 한 번 더 확인해 줘. 하나라도 실패하면 배포하지 말고 원인부터 찾아 줘.
2. 배포: main 브랜치를 GitHub에 push하고, 저장소 루트(/)를 서빙하도록 GitHub Pages를 켜 줘. 빌드 단계는 없다.
   push와 Pages 설정은 공개 저장소를 바꾸는 작업이니, 실행하기 직전에 나한테 한 번 확인받아 줘.
3. 배포 완료 확인: Pages 빌드 상태가 built가 될 때까지 기다려 줘.
4. 배포 주소 검증 (PC): 배포된 주소를 열고 아래를 확인해 줘.
   - style.css, src/app.js, src/todo-view.js, src/todo-store.js가 모두 200으로 받아지는지 (대소문자나 경로 오류 확인)
   - 콘솔에 오류가 없는지
   - PRD 8.2절 체크리스트 전체
   GitHub Pages는 파일을 약 10분 캐시하니, 확인 전에 강력 새로고침(Ctrl+F5)을 해 줘.
5. 휴대폰 확인 요청: 나한테 휴대폰으로 같은 주소를 열어 아래를 확인해 달라고 요청해 줘.
   - 가로 스크롤 없이 보이는지
   - 체크박스, 수정, 삭제 버튼이 손가락으로 무리 없이 눌리는지
   - 20-30자짜리 한글 제목이 읽기 괜찮은지
   - 한글 마지막 글자를 조합하는 중에 Enter를 눌러도 제목 전체가 저장되는지
   - 새로고침 후 데이터가 남아 있는지

반드시 지킬 것:
- 내가 휴대폰 확인 결과를 알려 주기 전에는 완료라고 보고하지 마.
- 확인하지 못한 항목이 있으면 숨기지 말고 그대로 보고해 줘.

끝나면 배포 주소와 항목별 검증 결과를 정리해서 보고해 줘.
```

## 완료 확인

- 배포 주소에서 PC와 휴대폰 모두 PRD 8.2절 체크리스트를 통과합니다.
- PRD 10절의 완료 기준 세 가지를 모두 만족합니다.
