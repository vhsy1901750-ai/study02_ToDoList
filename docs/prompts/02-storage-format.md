# 2단계: 저장 형식과 데이터 검증

새로고침해도 데이터가 남도록 상태를 문자열로 바꾸고, 망가진 저장 데이터를 알아보는 로직을 만듭니다. 아래 상자의 내용을 그대로 복사해 Claude Code에 붙여 넣어 주세요.

```text
docs/PRD.md를 읽고 2단계를 진행해 줘. 1단계에서 만든 src/todo-store.js에 저장 형식 처리를 더한다.

할 일:
1. serializeState(state)를 만들어 줘. 상태를 JSON 문자열로 바꾼다.
2. parseState(raw)를 만들어 줘. 돌려주는 값은 { state, error }다.
   - raw가 null이면(처음 실행) 초기 상태와 error: null
   - JSON 파싱에 실패하거나 PRD 6절의 "형식 불일치"에 해당하면 초기 상태와 error: "corrupt"
   - 정상이면 읽은 상태와 error: null
3. 테스트를 추가해 줘. 값 없음, 깨진 JSON, 정상 데이터 왕복(serializeState → parseState), 그리고 형식 불일치는 경우마다 따로 테스트한다.

형식 불일치로 봐야 하는 경우 (하나라도 해당하면 corrupt):
- 최상위가 객체가 아니거나(null, 배열 포함) version이 1이 아님
- todos가 배열이 아님
- filter가 FILTERS에 없는 값임
- 할 일 중 하나라도 규칙을 어김: id가 빈 문자열이거나 문자열이 아님, 제목이 비었거나 101자 이상이거나 앞뒤에 공백이 있음, 카테고리가 허용 값이 아님, done이 불리언이 아님, createdAt이 숫자가 아님, 할 일 자체가 객체가 아님

반드시 지킬 것:
- 제목 검사는 1단계에서 만든 제목 정리 함수를 다시 써서 한 곳에서만 규칙을 관리해 줘.
- 이 파일에는 여전히 localStorage를 들이지 마. 실제 저장은 3단계에서 app.js가 맡는다.
- 테스트를 먼저 쓰고 실패를 확인한 뒤 구현해 줘.

끝나면 npm test 결과를 보여 주고, 커밋한 뒤 멈춰서 보고해 줘.
```

## 완료 확인

- `npm test`가 모두 통과하고, 형식 불일치 경우가 하나씩 따로 테스트돼 있습니다.
