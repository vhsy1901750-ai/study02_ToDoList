# 4단계: 사용자 동작 연결

추가, 완료 체크, 수정, 삭제, 탭 전환, 완료 항목 정리가 실제로 동작하게 연결합니다. 아래 상자의 내용을 그대로 복사해 Claude Code에 붙여 넣어 주세요.

```text
docs/PRD.md를 읽고 4단계를 진행해 줘. 3단계에서 만든 화면에 사용자 동작을 연결한다. 대상은 PRD 3.4절부터 3.9절까지다.

할 일:
1. src/app.js에 update(nextState) 함수를 만들어 줘. 순서는 이렇다.
   ① 수정 중이던 항목을 닫는다(editingId = null).
   ② nextState가 지금 상태와 다른 객체일 때만 상태를 바꾸고 localStorage "todo-app"에 저장한다.
   ③ 화면을 다시 그린다.
2. 추가: 폼 제출(버튼, Enter)로 추가한다. 성공했을 때만 입력칸을 비우고, 커서는 입력칸에 남긴다. 빈 제목은 무시한다.
3. 탭: 탭을 누르면 필터를 바꾸고 저장한다. 추가 폼의 카테고리 기본값을 그 탭으로 맞춘다(전체 탭이면 업무).
4. 완료 체크, 삭제: 목록 <ul> 하나에 click 이벤트를 위임하고 data-action으로 구분한다. 삭제는 "이 할 일을 삭제할까요?" 확인 창을 거친다.
5. 완료 항목 정리: "완료한 할 일 N개를 삭제할까요?" 확인 창을 거쳐 현재 탭의 완료 항목을 지운다.
6. 수정 (PRD 3.7절): 수정 버튼을 누르면 그 자리가 제목 입력칸, 카테고리 선택, 저장 버튼, 취소 버튼으로 바뀌고 입력칸에 커서가 간다.
   - Enter나 저장으로 저장하고, Esc나 취소로 취소한다.
   - 빈 제목이면 저장하지 않고 수정 화면을 그대로 둔다.
   - 한 번에 한 항목만 수정할 수 있다. 수정 중에 다른 동작(추가, 체크, 삭제, 탭 변경, 정리)을 하면 저장 없이 닫힌다. 다만 삭제나 정리 확인 창에서 취소하면 바뀐 것이 없으므로 수정 화면을 그대로 둔다.

반드시 지킬 것:
- 변경 여부는 todo-store 함수가 같은 객체를 돌려줬는지(nextState !== state)로만 판단해 줘.
- 이벤트 리스너는 다시 그려지지 않는 바깥 요소(#tabs, #todo-list, 폼)에만 붙여 줘.
- 저장 버튼에는 data-action을 붙이지 마. 폼 submit 이벤트로만 처리한다.

확인 방법:
- 3단계처럼 python -m http.server 8000으로 열고 PRD 8.2절 체크리스트를 처음부터 끝까지 실제로 눌러 보며 확인해 줘.
- 새로고침한 뒤 목록과 선택한 탭이 유지되는지 꼭 확인해 줘.

끝나면 체크리스트 항목별 결과를 보고하고, 커밋한 뒤 멈춰 줘.
```
